## 本轮发现与修复

同一个服务器／账号在不同目录独立创建两个 catalog 时，原先六类游标只检查账号仓库 `StoreId`，另一数据库会接受不属于自身的分页位置，可能造成漏读或错误续页。

现在游标统一绑定 `StoreId + source_namespace`。`source_namespace` 是 catalog 已有的持久身份，在创建服务时复用已有 Info 查询读取；没有新增 schema、迁移、自动删库或每次查询的额外数据库读取。平台路由仍使用原有账号仓库标识。

修复前任务游标用例失败，其余五类游标在修正准备失败夹具后也全部失败，均明确显示跨库调用没有抛出应有的参数错误。修复后验证跨库拒绝与同库重开继续，避免只测试限制。

## 复现入口

从包目录运行原生新增用例，使用现有库，无须重建 SQLite：

```sh
python3 Runtime/MediaBackup/Native~/tests/business_boundaries.py \
  --core Runtime/Sqlite/Plugins/macOS/libuiframe_sqlite.dylib \
  --repository Runtime/MediaBackup/Plugins/macOS/libuiframe_backup.dylib -v
python3 -m unittest discover -s Tools~/BackupServer -p 'test_*.py' -v
```

Unity Test Runner 的 EditMode 运行 `UIFrame.Regression.Media` 与 `UIFrame.Regression.Backup`。只运行新增用例时选择 `MediaBusinessBoundaryTests` 与 `MediaBackupCursorTests`。运行包含 `MediaIntegration` 的全套用例前，在另一终端启动临时服务，完成后关闭：

```sh
python3 -u Tools~/BackupServer/integration_server.py
```

新增场景应继续归入上表的业务边界：同时验证失败、真实资源归属和相邻正常路径；回归失败先区分夹具错误与业务错误，不直接修改期望值让测试通过。

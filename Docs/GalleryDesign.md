# 图片、图库与备份设计

本文记录当前实现的设计与边界。公开 API、配置、示例、故障处理步骤见 [使用说明](Gallery.md)；HTTP 字段的机器契约见 [OpenAPI](../Tools~/BackupServer/backup-protocol.openapi.yaml)。通用错误约定见 [ErrorContract](ErrorContract.md)。

## 范围与版本

系统选图、照片库和授权目录读取、图库索引、共享缩略图、手动及运行期间自动备份、原生后台传输、批量控制、回执下载和有界清理已实现。新照片的系统后台发现、尚未准备文件的后台导出、视频 / Live Photo / RAW 成套备份、双向删除、自动删除原图、端到端加密和换机 / 重装恢复不在当前范围。系统强行结束应用后的传输不作保证。

备份业务 ABI 4，catalog schema 5，图库 library schema 3，通用 SQLite ABI 3，HTTP 仅 v2。两个业务库只接受当前 schema；不迁移、自动删除或重建旧开发库。新验证环境须显式使用空目录。照片业务复用通用 SQLite 核心，不修改 SQLite 上游源码，也不在平台适配层复制业务 SQL。

## 组件与数据归属

| 组件 | 职责及持久事实 |
| --- | --- |
| `GameGallery` / `GameImageDirectory` / `GameImageReader` | 系统选择、来源枚举、受控预览及导出；不修改用户原图 |
| `ImageLibraryIndex` | 独立 `library.sqlite`，保存范围、成员、版本和变化日志；负责分页与增量 / 完整核对 |
| `ImageThumbnailCache` | 进程内共享纹理租约与空闲 LRU；不作为持久照片副本 |
| `ImageBackupService` / `AutomaticImageBackup` | 固定提交成员和来源控制范围、持有来源租约、串行准备、自动发现与用户操作 |
| 原生 `BackupRepository` | 独立 `catalog.sqlite`，保存任务、执行代次、协议请求、回执、范围和资源所有权；C# 与平台回调共用同一状态机 |
| Android / iOS 适配 | 系统调度、受保护凭据、流式 HTTP 和实际资源释放；不另存业务状态 |
| 业务服务 / 私有存储 | 账号隔离、批量仲裁、上传授权、独立文件接收、服务端核验与不可变备份记录 |

仓库路径由私有根目录及标准化服务器地址、账号的 SHA-256 分隔；每个 catalog 另有持久 `source_namespace` 区分独立安装或数据库。图库与备份库生命周期独立。任务、回执、变化、操作明细、清理故障及准备失败游标绑定所属数据库身份；跨库或筛选条件不匹配时明确拒绝，同库重开可续页。任务分页固定创建上界但状态实时变化，不是冻结快照。回执、来源处置和最小操作身份独立于可清理的任务历史。

### 原生仓库接口

仓库命令输入为 `uint32` 数量及带类型的 SQLite 值，输出为有界表。单次输入 / 输出最多 1 MiB、200 行，进程内最多受理 16 个调用；命令在工作线程执行。控制请求文件另有 8 MiB 预算，列表查询只返回调度元数据和受保护引用，不装载请求正文。命令编号属于当前 ABI，适配器必须依照返回的准入、所有权和释放事实推进：

| 命令组 | 当前语义 |
| --- | --- |
| `Prepare(2)`、`TryPrepare(77)`、`PreparationEligibility(78)`、`StopPreparation(79)`、`Seal(3)`、`AcceptItem(96)`、`FailItem(97)`、`RecoverPreparations(55)`、`Submission(98)` | 固定提交成员，独立容量准入，单项刷盘 / 接受 / 失败；恢复只失败中断且未接受的成员。等待句柄不自动撤销准备。 |
| `Claim(9)`、`Handoff(74)`、`SystemScheduled(95)`、`Attempts(23)`、`Ready(62)` | 认领代次、持久交接、系统真实受理及未释放资源 / 桌面就绪分页。服务器请求不是交接前置条件。 |
| `ControlCreate(80)`、`ControlSeal(81)`、`Submitted(82)`、`Start(83)`、`ControlValidate(84)`、`Apply(85)`、`ControlFail(86)`、`Release(87)`、`Recover(88)`、`Control(104)`、`Controls(89)` | 持久化固定控制请求；整包验证后原子应用逐项结果；HTTP 与事务分开，释放只在平台实际完成后记录。 |
| `Uploads(90)`、`UploadStart(91)`、`UploadEnd(92)`、`UploadRelease(93)`、`UploadReject(106)`、`ProtocolActions(94)`、`Wake(105)`、`Configure(99)` | 独立文件准入、传输与资源释放；PUT 成功转确认，不生成回执。过期描述先释放再重新 Plan。 |
| `ProtocolReconcile(101)`、`Resume(103)`、`Release(102)`、`Action(14)`、`Pause(15)` | 未知远端结果仅在旧资源实际释放后显式核对；取消意图不因普通核对而撤回；全局暂停与逐项意图分别持久化。 |
| `Operation / Select / Apply(40–42)`、`Cleanup(18/19/21)`、`Failures(76)`、`ProtocolCleanup(100)`、`ControlCleanupFailures(107)`、`ControlCleanupRetry(108)` | 固定批量目标、逐页执行与等待实际释放；文件故障仅在持久隔离后继续，重试只针对指定文件。 |
| `Scope / scan / disposition(30–36, 69–73)`、`ConfirmScope(109)`、`History / metadata pruning(50–52, 67–68, 72)` | 范围代次阻止失权后的新准入；确认不升级旧任务代次；按稳定索引有界清理且保留回执、来源处置及最小操作身份。 |

任务状态编号为 0 queued、1 uploading / registration、2 confirming、3 completed、4 paused、6 needs attention、7 failed、8 canceled、9 preparing；协议阶段为 0 Plan、1 文件 PUT、2 Query、3 terminal。`Completed` 与已接收远端尝试的 `Canceled` 必须有权威协议结果。平台不得将暂停请求、回执应用或 C# 关闭当作系统任务、流或凭据已经释放。

## 获取、索引与内存

系统选择器通常无需整库授权；照片库查询由业务显式请求权限，Limited 只暴露获准成员。普通目录、SAF 和 iOS 书签目录按来源各自保存身份与授权。来源失效、权限撤销、书签过期、单项文件消失和网络失败分别保留原错误，不将普通缺失推断为整库失权。

枚举和索引按页工作，每页最多 200 项，单次索引写入最多 32 张元数据。持久范围代次、权限代次、扫描身份和变化日志决定游标有效性；日志截断、监听中断、权限或连续性变化要求完整核对。完整扫描先核对边界，失败不提交缺失删除。PhotoKit 使用 fetch result 变化，Android 使用 ContentObserver 和 MediaStore version / generation，目录监听图片及目录结构；SAF / 书签提供者不能承诺可靠增量。每索引最多观察 16 个范围、每范围 32 个订阅；观察者由订阅与在途刷新共享，最后的所有者等待注销完成。

目录索引的内容版本使用流式哈希证明，普通 `ImageReference.FromFile` 只有便宜的元数据版本。索引枚举排除符号链接 / 重解析点。准备复制时复用内容证明并核对复制前后元数据；封存文件由仓库刷盘，上传及下载另行校验 SHA-256。来源版本未知时，依赖版本的缓存与备份拒绝受理。Limited 成员集合变化才推进相应权限代次；内容或名称变化不会触发范围确认。

图片处理共用一个解码 / 变换槽，导出原始字节不占该槽。请求准入最多 128 个在途键、512 个等待者和 1 MiB 请求元数据；缩略图空闲预算默认 32 MiB / 128 键。相同键共享处理但等待者分别取消；租约释放前不能销毁已交付纹理。预算与统计只覆盖本图片管线，不代表进程峰值内存。桌面预览限制 JPEG / PNG、16 MP 源图及 128 MiB 编码缓冲；移动端按目标尺寸原生解码。源文件与预览纹理的所有权见使用说明。

## 登记、准备与交接

一次 `SubmitAsync` 登记 1–32 张，先取得全部来源租约，在事务中固定成员、顺序、来源版本和控制范围，立即返回可等待的句柄。`WaitAsync` 只等待各成员准备、失败或执行端接收，不等待上传与确认；取消等待不撤销登记。`CancelPreparationAsync` 持久停止尚未接受的成员，必须等实际导出结束后才释放预留及租约。准备接受之后，任务控制与资源归属由仓库和执行端继续持有。

容量准入与文件生产分离：最多 128 个未收尾登记成员、1 个实际未封存生产者、64 个封存文件；默认暂存预算 1 GiB，单文件最多 512 MiB，另留 16 MiB 文件系统余量。容量不足保留候选等待事件或有界周期核对，不作为单项失败；单个来源损坏只失败对应成员。文件复制、哈希、HTTP 和系统调度均在 SQL 事务之外；仓库以短事务记录准入、Seal、Accept、Claim、Handoff 和系统受理的顺序。移动端受理不等于系统立即执行，更不等于远端确认。

手动任务和不同自动范围各有固定控制权；共享回执不转移任务归属。自动扫描每轮最多登记 128 项，不等待其准备完成。范围失权先关闭新准入并推进代次，再逐页暂停所属任务；确认范围要等旧准备停止，之后新候选可重新登记，已接受而暂停的任务须单独恢复。授权确认不能掩盖数据库、凭据或清理故障。

## 协议、身份与状态

唯一 HTTP v2 流程为批量 Plan、独立文件 PUT、滚动批量 Query 和按需批量 Cancel；没有客户端 commit。Plan / Query / Cancel 最多 32 项，请求上限 256 KiB、响应 512 KiB、单描述 8 KiB。文件 PUT 只说明字节持久接收；只有服务端针对账号、任务、代次、来源版本、大小与 SHA-256 的有效回执才能置为 `Completed`。已核验内容可在账号内复用，不跨账号共享存在性；同内容的不同来源仍有独立备份记录。

`clientTaskId`、`attemptGeneration`、`requestId`、`uploadId` 分别固定任务、执行代次、控制请求和上传尝试。请求 ID 的成员及参数不可变化。收到响应时先验证整个信封与全部成员，再原子应用逐项结果；无效末项不能让前项先写入。迟到回调只能影响其代次，有效迟到回执仍可确认。确认与取消在服务端原子仲裁；取消先成立时墓碑阻止旧上传发布，已确认时返回回执。

每仓库最多两个文件上传和一个当前控制请求。Plan 聚合至多 250 ms，初次 Query 聚合 1 s；Wi-Fi-only 和任意网络各自保存当前 / 未来 Query 名额及轮换位置，取消优先。上传成功释放上传槽位，再按服务器 `nextCheckAt` 核对。第 256 次 Pending 或 24 小时期限结束自动确认并进入 `NeedsAttention`；系统唤醒不保证精确到期。请求结果未知、传输响应丢失和结构不符不会自动重发；必须在旧系统任务、流和凭据实际释放后显式 `ReconcileTaskAsync`。明确失败且暂存文件有效才可 `RetryAsync`，准备失败需重新提交来源。

业务与上传 origin 必须是可信最终终点，服务、网关和存储均不得重定向。桌面 / Android 禁止自动跟随；iOS 后台 URLSession 只能事后检查最终 URL 和可用 metrics，无法阻止跳转前的字节转发。生产接入必须单独验证这一边界。业务 Bearer 不发送到私有上传端；Android 凭据由 KeyStore 保护，iOS 用 Keychain 引用，桌面凭据引用仅对当前进程有效。数据库不存明文凭据或上传描述。

## 生命周期、故障与清理

Android 自动模式由 JobScheduler 调度，用户主动模式在 API 34+ 使用用户主动数据传输 Job、API 25–33 使用前台服务；iOS 使用文件式后台 URLSession。系统任务接收、启动、网络结束、回执应用和实际资源释放分别持久记录。暂停 / 取消只是意图，不伪造系统任务、文件和凭据已释放。全局暂停还原子停止未接受准备；恢复不复活它们。Android 强行停止、iOS 用户划掉与首次解锁前的执行行为均不作承诺。

未知数据库提交结果会阻止依赖它的新工作，保留可能交接的资源与原异常，待确认原所有者已结束后显式恢复。单个文件清理错误若已可靠持久隔离，不阻断其他文件；无法隔离的数据库错误直接传播。历史清理逐页重检任务、回执、系统任务、凭据及控制文件的引用，不凭预览或 TTL 删除在用文件。显式清理每轮最多 200 个逻辑项；参考服务维护每轮最多 64 个候选。控制正文删除后保留少量诊断记录 30 天。失败文件只按指定 ID 显式重试。

参考服务单数据目录只允许一个进程持有，启动取得跨进程锁，关闭先等待 HTTP、核验与数据库收尾。上传尝试和无引用发布对象有独立 24 小时保留规则；已确认或仍有引用的对象不受临时 TTL 删除。核验工作线程不可隔离地失败时，新 Plan、未确认状态和新 PUT 返回 503；已确认查询 / 下载及取消可用，在途已落盘文件保留到显式重启后核验。参考服务是本机协议与故障验证实现，不代表正式认证、对象存储、容量或灾备设计已验收。

### 真机验收步骤

1. 手机与电脑网络互通，启动参考服务并配置局域网地址、开发 HTTP 或 HTTPS；iOS 配置局域网访问说明。运行移动端 GalleryDemo，填写运行时凭据。
2. 选取多张图片（含大文件），点击备份，确认显示提交状态。切换到其他应用 / 锁屏；检查服务器已提交列表。回到应用刷新，已完成文件必须能下载并核对 SHA-256。
3. 在只允许非计费网络时切换 Wi-Fi / 蜂窝，确认平台条件有效。iOS 允许非计费有线网络，与 Android 的严格 Wi-Fi 条件不同。
4. 上传中暂停、恢复、取消；确认释放前暂存文件仍在，恢复不会产生两条同任务上传，取消不删除服务器已有副本。
5. 分别测试系统回收、Android 强制停止 / 重启、iOS 用户划掉应用，再次打开并 ProcessAsync。记录实际调度延迟，不要求强制退出后继续上传。
6. 令牌失效应 NeedsAttention；更新令牌后 Retry / ProcessAsync。退出账号先 PauseAsync 等待完成，再关闭服务；切换账号使用独立目录。
7. 测试服务器中断、错误校验、暂存文件删除、原生记录损坏。不得显示假完成；错误必须可见，普通失败不静默业务重试。

## 2026-09-29 性能优化与验证

本轮保留系统照片选择器入口，优化 Unity 展示图片、持久队列和本机服务器：

## 2026-09-29 内存审查修复

本轮将保护放在共用读取、分页和持久化边界，没有为聊天或自动备份建立另一套解码规则。

- 预览与转码串行执行，覆盖原生异步请求和 Unity 解码；Unity 纹理解码期间取消先完成所有权交接，再释放纹理。运行时等待销毁帧后放行下一次。原字节导出仍按文件流处理。
- 预览默认没有 CPU 像素副本和 mipmap；确需读取像素时显式 `Readable=true`。目标像素预算默认 4 × 1024²，最多 16 × 1024²，超出明确失败。Android 旧解码器更早采用采样，错误路径统一回收位图；iOS 目标渲染使用标准色彩范围。
- 目录 / 照片库新增每页最多 200 条的访问接口；回调返回 false 正常停止、异常则失败。自动扫描使用此入口，移动端元数据先按页写入磁盘暂存，再逐页读取；显式 Query 快照仍随照片数占用内存。
- 不含历史的首次基线逐页写入、完成后提交标记，取消不接受半份基线；并发冷加载共享一个读取任务，热查询只复制失败项。
- iOS 目录书签登记一次，图片 ID 使用短标识与相对路径。JPEG 头解析只保留一个至多 65535 字节的段缓冲。备份控制 / 错误响应按流读取并限制为 64 KiB，含未知长度响应。

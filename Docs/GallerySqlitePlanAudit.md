| 复审项 | 原问题 | 本轮处理及证据边界 |

| F1 · P1 | Claim 后、服务端会话/凭据尚未交接时，原生调度器已经能取得任务并 START | 共享仓库新增 Handoff 与 Schedulable。submission_state 为0/1/2，分别表示前台持有/已交平台/已绑定系统任务；原生 Start 只接受2。托管执行者保留直接 Start 路径。终结但未交接的代次只开放给资源清理；恢复不会代替平台宣告凭据已释放。两个平台 executor 的未交接、未绑定、绑定、重新绑定与凭据释放契约均有原生回归。 |

## 实施交付缺口的处理

- **平台扫描边界**：Begin持久保存平台上界，Finish写回完成边界。Android比较各外部卷的版本/generation及观察序号；iOS使用观察者持有的PHFetchResult和修订。边界变化使扫描失败，不能提交“已核对”。重开仍执行完整核对，未伪造可跨进程恢复的PhotoKit token。
- **虚拟列表**：新增 GalleryVirtualListDemo / GalleryThumbnailCell，使用已有LoopScroll，有界200条元数据页、可见单元复用、独立租约、离屏释放和旧请求隔离。样例在独立消费程序集编译通过。它是分页虚拟列表，不宣称已经完成5000张连续滚动的产品验收。
- **内存计量**：Destroy统一跟踪图片管线的待销毁纹理，覆盖加载后取消/失效及变换临时纹理；增加在途解码估算。缓存关闭只等待自身工作。估算不代替PhotoKit、Bitmap、驱动、RenderTexture池和进程峰值实测。
- **发布自动化**：新增四目标GitHub Actions原生构建，macOS/Windows宿主契约、schema/进程恢复检查，以及二进制/符号/清单归档。补齐仓库Windows宿主构建入口和macOS dSYM。配置尚未在远端运行；Unity许可、设备农场、项目遥测及告警未接入。

# 错误处理契约

成功必须兑现 API 承诺；失败必须可观察。失败后只清理框架拥有的资源，不猜测调用者意图，不自动重试失败操作，不伪造成功。

## 结果分类

1. 成功：全部承诺的步骤完成后，才返回成功或完成任务。
2. 预期未完成：查询不存在使用明确的 Try/false/null；主动取消使用取消状态。各接口必须声明这些含义。
3. 错误：非法参数、无效配置、生命周期冲突和执行异常必须抛出异常或使任务失败。不得用 false、null、取消或默认值掩盖错误。

## 输入与副作用

公开入口在产生副作用前验证参数和当前可确定的前置条件。加载、回调等执行期间才能发现的错误，在发生处传播并清理；不为预先证明整个操作必定成功而重复执行工作或增加无关检查。显式无效值直接拒绝，不截断、不替换。默认值只适用于接口声明的省略值。

接口应声明接收的是完整有效配置还是当前模式使用的配置，并按该承诺校验；不能一面声明字段不参与当前模式，一面未加说明地用它拒绝操作。可选能力必须预先声明；平台原始数据适配不得扩展成对调用者错误输入的容错。

## 回调与批处理

回调异常终止当前依赖它的业务操作或批次，并保留原异常和堆栈。已完成步骤不自动回滚，未执行步骤不得标记为成功。调用者负责业务回调的副作用，框架负责自身状态和资源，不自动续跑或重试失败操作。

重试是再次执行已经失败的那次操作，试图使其完成；同一回调处理后续独立消息属于新操作，不因委托相同就视为重试。一次调用失败也不证明该回调永久失效。失败后是否结束整个计时任务或解除订阅，由模块明确约定，不能推广为“所有回调抛错都自动注销”。

设计时按操作依赖与共享状态选定简单、固定且足以保证正确性的失败边界，不要求穷尽所有可继续的调用组合。共用类型、容器或 Runner 本身不证明所有工作相互依赖。扩大停止范围必须有具体依据，例如共享状态已不可信或后续步骤依赖失败结果，不能仅以“严格处理错误”为由停止整个系统。模块须说明批次范围、未执行工作的归属及显式收尾方式。执行未失败的独立工作不等于重试失败操作，也不代表必须在当前批次继续执行。

设计和审查失败边界时，结合错误来源和收尾后的状态：失败项是否正确摘除或隔离、资源所有权是否明确、共享容器是否仍满足不变量、后续工作是否依赖失败结果。运行时按选定的边界处理，不为逐次判断故障范围而增加动态依赖分析、全局状态扫描或自动修复。不能仅凭异常类型推定系统损坏或继续运行安全。

## 所有权与清理

每项资源只有一个释放责任方。操作失败时释放已经获取但尚未转移的资源。已有主异常时保留同一异常，后续清理异常单独记录；没有主异常时，第一个清理异常作为主异常。

最终 Dispose/Shutdown 必须尝试所有归其所有的清理，最后传播主异常，不能仅记录日志后返回成功。可能失败且互不依赖的资源释放应分别处理，不要求给普通状态赋值等收尾语句逐一添加异常捕获。重复释放只允许用于明确声明幂等的清理接口。

移交销毁或释放前先摘除可复用引用，释放失败也不自动重试。同一共享加载的所有等待者必须结束；清理异常不能跳过任务完成或操作计数收尾。业务清理按已声明的批次策略处理；最终清理则尝试其余资源，不能只按 Clear、Dispose 等方法名推断职责。

故障记录与资源状态分别如实维护：释放已完成不等于业务成功，历史错误也不能代替当前资源是否仍被占用的判断。新增故障锁或重入限制须说明保护的状态、限制范围和解除条件；没有安全的局部恢复流程时可以要求显式 Shutdown，不为此添加自动恢复或通用重置入口。

## 生命周期与异步完成

每个异步接口应声明结果的确定点和成功所需步骤。结果尚未确定时，必要步骤失败不能报告成功或伪装成主动取消；结果确定后，不被后续独立事件改写。主动取消的含义和取消期间清理失败的传播方式由该接口明确约定。

内部模块向上传播原异常。Unity 事件、帧更新和无人等待的后台任务作为最外层边界，记录未处理异常并按已声明的失败边界停止工作。不得通过捕获异常继续依赖失败操作成功的步骤；传播层不重复记录同一个主异常，清理产生的独立次级错误另行记录。

停止自动驱动不能使已接受的异步等待永久悬挂，也不能封锁取消、资源释放和最终 Shutdown。因驱动故障而无法完成的等待以原故障结束，不伪装成主动取消；已经确定的成功或主动取消结果不改写。拒绝新工作的范围应与停机范围一致，恢复必须由调用者显式发起。

## 模块策略

通用原则不替代模块的具体承诺。Popup 的关闭与结果交付见 [UI 使用契约](USAGE.md#统一失败语义)，Timer 的失败任务移除与驱动故障停机见 [Timer 异常处理](Timer.md#11-异常处理)，红点的失败订阅隔离见 [红点监听](RedDot.md#3-手动监听)，对象池的 Clear 与 Dispose 见 [对象池](Pool.md)。UI 销毁失败与 EventSystem 独占见 [错误与生命周期契约](../README.md#错误与生命周期契约)。

通用规则的澄清不隐式改变已声明的模块行为。改变停止范围、重入限制、配置有效范围等策略时，必须同时更新对应实现、文档与行为验证；不能仅凭通用条款直接删除保护，也不能将已有模块策略复制成其它模块的默认限制。

## 审查与验证

逐个入口确认成功条件、允许的未完成结果、异常传播、状态提交和资源归属。回归验证应覆盖依赖步骤遇错停止、不报告假成功、不自动重试失败操作、最终清理继续执行、主异常不被替换及相邻正常路径。按变更影响选择验证范围，已有测试足以覆盖时无需重复新增；不能只验证新增限制会抛错。

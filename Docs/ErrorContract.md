# 错误处理契约

成功必须兑现 API 承诺；失败必须可观察。失败后只清理框架拥有的资源，不猜测调用者意图，不重试业务，不伪造成功。

## 结果分类

1. 成功：全部承诺的步骤完成后，才返回成功或完成任务。
2. 预期未完成：查询不存在使用明确的 Try/false/null；主动取消使用取消状态。各接口必须声明这些含义。
3. 错误：非法参数、无效配置、生命周期冲突和执行异常必须抛出异常或使任务失败。不得用 false、null、取消或默认值掩盖错误。

## 输入与副作用

公开入口先验证输入，再产生副作用。显式无效值直接拒绝，不截断、不替换。默认值只适用于接口声明的省略值。可选能力必须预先声明；平台原始数据适配不得扩展成对调用者错误输入的容错。

## 回调与批处理

回调异常终止当前依赖它的业务操作或批次，并保留原异常和堆栈。已完成步骤不自动回滚，未执行步骤不得标记为成功。调用者负责业务回调的副作用，框架负责自身状态和资源。不自动续跑或在下一帧重试失败回调。

## 所有权与清理

每项资源只有一个释放责任方。操作失败时释放已经获取但尚未转移的资源。已有主异常时保留同一异常，后续清理异常单独记录；没有主异常时，第一个清理异常作为主异常。

Dispose/Shutdown 必须尝试所有归其所有的清理，最后传播主异常，不能仅记录日志后返回成功。重复释放只允许用于明确声明幂等的清理接口。

移交销毁或释放前先摘除可复用引用，释放失败也不自动重试。同一共享加载的所有等待者必须结束；清理异常不能跳过任务完成或操作计数收尾。业务 Clear 遇首错停止并保留未处理项，最终 Dispose/Shutdown 则继续清理其余项。

## 生命周期与异步完成

Popup 的结果成功表示“提交结果且关闭操作成功完成”。关闭、销毁或关闭后必要导航失败，结果等待者与发起调用者均收到失败；正常关闭且没有结果才取消。失败优先于成功和取消。

内部模块向上传播异常。Unity 事件、帧更新和无人等待的后台任务作为最外层边界，记录一次未处理异常并停止失败工作。不得通过捕获异常继续业务或启用 Timer Continue 策略。

停止自动驱动不能使已接受的异步等待永久悬挂，也不能封锁取消、资源释放和最终 Shutdown。因驱动故障而无法完成的等待以原故障结束，不伪装成主动取消；已经确定的成功或主动取消结果不改写。停止后的业务入口仍拒绝新工作，恢复必须由调用者显式发起。Timer 的具体行为见 [Timer 异常处理](Timer.md#11-异常处理)。

## 审查与验证

逐个入口确认成功条件、允许的未完成结果、异常传播、状态提交和资源归属。回归验证应覆盖失败后不继续业务、不报告成功、不重复回调、清理继续执行、主异常不被替换及正常路径。任何契约变更必须同步接口文档与测试。

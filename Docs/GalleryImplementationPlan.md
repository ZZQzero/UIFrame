# 图片获取、相册与图片备份实施方案

日期：2026-09-29  
状态：基础实现与验证进行中。本文保留完整目标，不代表所有阶段均已完成；实际接口与限制以 [Gallery.md](Gallery.md) 为准，已执行验证见 [GalleryValidation.md](GalleryValidation.md)。  
适用项目：UIFrame / Unity 6000，UniTask，UGUI。

2026-09-30 后续实施入口：[长期照片备份与图库性能实施计划](GalleryLongTermBackupPlan.md)。SQLite、图库增量刷新、共享缩略图、批量任务管理及清理策略按该文档实施；下文对应的早期规划由新计划细化，不能作为当前已实现能力。

SQLite 通用能力规划在 [Runtime/Sqlite](../Runtime/Sqlite/README.md) 中作为商业游戏的独立存储模块实现：统一官方引擎、原生核心和 C ABI，游戏仓库与图库按职责接入；照片任务由一份共享原生业务仓库管理，平台只适配系统能力。具体预算和发布门槛以该模块实施计划为准。

## 1. 目标与范围

自研 Android、iOS 原生适配，对业务提供一致的图片选择、读取和释放接口，服务于头像、聊天附件、自定义背景和本地图库；在其上增加独立的图片备份模块，将用户指定范围的图片可靠地上传服务器。

完整目标分为四个独立能力：

| 能力 | 交付行为 | 不代表什么 |
| --- | --- | --- |
| 系统选图 | 打开系统选择器，单选或多选图片 | 不要求获得整个照片库的读取权限 |
| 目录浏览 | 枚举指定可访问目录中的图片 | 不保证任意手机路径均可访问 |
| 相册浏览 | 查询应用获授权访问的相册和图片，用自己的 UI 展示 | 不承诺读取未授权的照片 |
| 图片备份 | 手动备份、指定范围备份和用户主动开启的自动备份 | 不承诺手机后台持续运行或拍照后立即上传 |

通用读取层提供缩略图、预览图和可供上传使用的文件。备份模块另行负责上传协议适配、持久队列、服务端确认和显式配置的业务重试；图片读取层仍不自动重试。消息发送、头像裁剪、保存到相册、拍照、视频、双向同步及自动删除手机原图不在本轮范围内。

基础实施顺序：系统选图 → 普通目录浏览 → 自定义相册浏览 → 外部目录授权。第五阶段为独立的图片备份扩展：手动备份在第一阶段及服务端契约完成后即可实施，相册自动发现依赖第三阶段，外部目录备份依赖第四阶段。每个阶段单独构建、验收和交付，不等待全部能力完成。

## 2. 已确认的项目条件

- `Runtime/Load/UIImageLoader.cs` 只管理 YooAsset Sprite 及其句柄，保持现有职责。外部图片不伪装成 YooAsset 资源。
- `UIFrameScope.Register(IDisposable)` 可登记图片资源；`OpenCancellationToken` 可取消面板关闭前尚未完成的工作。
- 当前 Runtime 使用单一 `UIFrame.Runtime.asmdef`。第一版沿用，不为新模块提前拆分整个包。
- 当前宿主 Android 最低 API 为 25，Target SDK 为自动选择。不得为了接入图片模块直接提高宿主最低版本。
- 包中的错误语义与所有权遵守 [ErrorContract.md](ErrorContract.md)，开发要求遵守 [AGENTS.md](../AGENTS.md)。

### 平台支持基线

| 平台 | 第一阶段方案 | 发布前必须确认 |
| --- | --- | --- |
| Android API 33 及以上 | 平台 Photo Picker，单选 / 多选 | 系统选择上限、URI 读取、Activity 重建、目标 SDK 行为 |
| Android API 25–32 | `ACTION_OPEN_DOCUMENT`，过滤图片，支持请求多选 | 实际返回数量、URI 授权、云端文件读取 |
| iOS 14 及以上 | `PHPickerViewController` | 多选、云端资源、表示格式、回调和关闭时序 |
| iOS 14 以下 | 本期不提供系统选图，能力查询明确返回不支持 | 弱链接 / 可用性检查不能破坏低版本项目构建 |
| Unity Editor | 编辑器文件选择 + 测试用多选入口 | 内置文件面板不承诺多选；多选测试入口须明确标识 |
| Windows / macOS 正式包 | 第二阶段支持可访问目录读取 | 本期不承诺原生文件选择窗口或系统照片库浏览 |
| WebGL | 本期不支持 | 调用明确失败，不返回空成功结果 |

Android 按系统版本选择上述后端属于明确的平台适配规则。第一版不接入旧系统 Photo Picker 回移植能力，也不在某个后端执行失败后偷偷切换另一后端。

iOS 14 是功能支持基线，是否同步提高宿主部署版本由项目另外决定。开始原生开发前记录实际 Unity 补丁版本、Android SDK / JDK、Xcode、iOS 部署目标和构建目标；Android 编译 SDK 至少覆盖所用 API，第三阶段涉及 API 34 权限时须可编译相应接口。最终 SDK 组合以本项目构建验证结果为准。

备份代码建议放在独立的 `Runtime/MediaBackup/`，命名空间 `Game.Media.Backup`，包含 `GameImageBackup`、备份策略、持久任务仓库、上传客户端和平台后台适配。服务端实现与部署属于独立交付物，不放进 Unity Runtime。只有图片备份功能启用时，才接入所需网络、数据库与后台任务依赖。

若所选 Unity 构建链确实不支持该源码布局，再明确改用 AAR，并同时提交原生源码、构建脚本、工具版本与可复现步骤。不得只交付无法维护的二进制。第一版避免引入 AndroidX / Kotlin 依赖。

## 4. 第一阶段接口契约

以下为拟定签名，不可直接当作当前包的 API 使用。名称可在 P1 编码前小幅调整，但成功、取消与所有权语义必须先固定。

```csharp
// 在 Unity 主线程调用；不依赖 UI.Init()。
GalleryCapabilities GameGallery.GetCapabilities();

UniTask<ImageSelection> GameGallery.PickImagesAsync(
    ImagePickOptions options,
    CancellationToken cancellationToken = default);

UniTask<ImageTexture> GameImageReader.LoadPreviewAsync(
    ImageReference image,
    ImagePreviewOptions options,
    CancellationToken cancellationToken = default);

UniTask<ImageFile> GameImageReader.ExportFileAsync(
    ImageReference image,
    ImageExportOptions options,
    CancellationToken cancellationToken = default);
```

### 4.1 参数与能力

- `ImagePickOptions.MaxCount` 必须大于零；1 为单选，大于 1 为多选。默认 1，取消不是空集合。
- `GalleryCapabilities` 分别报告单选、多选、照片库查询是否支持，并报告已知的选择数量上限；未知上限不伪造固定数值。
- 已知数量上限在打开窗口前校验；Android 文档选择器无法可靠强制数量上限时，返回后检查，超出即报 `SelectionLimitExceeded`，清理本次暂存资源，不悄悄截断。
- 结果顺序采用平台返回顺序，不跨平台承诺用户点击顺序。聊天确认界面如允许排序，由业务维护。
- `ImagePreviewOptions.MaxEdge` 默认 2048，必须为正数；等比缩小，不放大小图。业务可显式请求更小尺寸。
- 第一版支持 PNG、JPEG；HEIC / HEIF 的预览和转码按设备解码能力报告。GIF、WebP、RAW 等未验收格式不默认列入支持清单。
- 无法显示的格式可以在文件导出模式下保留提供者交付的字节，但调用预览必须明确报错。扩展名与 MIME 不是解码成功的证明。
- `ImageExportOptions.Mode` 分为 `PreserveProvidedBytes`、`Jpeg`、`Png`。JPEG 必须声明尺寸、质量、透明区域背景色；质量范围为 1–100，非法值拒绝。
- `PreserveProvidedBytes` 不缩放、不转码；对仅转码模式有效的参数，不在保留字节模式中制造无关限制。

“原图”在框架中的准确承诺是“系统或文件提供者交付的图片表示”。它可能是编辑后版本或系统转换后的表示，不能声称必然是相机拍摄的原始字节。聊天是否显示“原图”按钮，由业务根据实际可提供的表示定义。

### 4.2 返回对象

| 类型 | 内容 | 释放与有效期 |
| --- | --- | --- |
| `ImageReference` | 不透明来源标识、文件名、MIME、可选尺寸 / 字节数 | 普通引用，不暴露为可任意读取的文件路径；遵循来源有效期 |
| `ImageSelection : IDisposable` | 只读 `Items` 集合、系统选图暂存文件 | 调用方拥有；释放后引用不得用于发起新读取 |
| `ImageTexture : IDisposable` | `Texture2D`、可按需创建并复用的 Sprite | 调用方拥有；统一销毁其创建的 Texture / Sprite |
| `ImageFile : IDisposable` | 模块临时文件的 `LocalPath`、实际格式及大小 | 调用方拥有；释放时删除模块创建的临时文件 |

未知元数据用可空字段表达，不能把未知尺寸写成可信的 0。`ImageReference` 不携带像素数据，不应为列表中的每张图创建 Texture。

文件名、MIME 和尺寸必须与最终输出相符；JPEG 转码后不能继续报告 `.heic`。

### 4.3 系统选图的成功确定点

1. 校验参数、支持能力和当前原生窗口占用状态。
2. 打开选择器，等待用户选择或取消。
3. 将选中的平台表示逐个流式复制到模块私有暂存目录。iOS 的临时文件必须在系统允许的有效期内复制；Android 使用 ContentResolver 读取 URI。
4. 全部图片暂存成功后，返回 `ImageSelection`。此时图片不依赖即将失效的原生回调临时路径，尚未解码成纹理。
5. 任意一项失败，整次选择任务失败，并清理已经创建的暂存文件，不交付半成功集合。不要自动重新打开选择器或重试下载。

选择期间允许系统提供者下载云端图片；因此窗口关闭不等于任务已成功。业务在等待期间显示加载状态并提供取消入口。未来如要部分成功，必须另行设计结果模型。

### 4.4 读取与导出

- 预览使用原生缩采样解码，并正确应用旋转 / 镜像信息；不得先在 Unity 中解码完整大图再缩小。
- 原生层输出方向已归一化的预览表示，Unity 层在主线程创建 Texture / Sprite。复制、解码和转码安排到适当的后台队列。
- `ExportFileAsync` 返回独立文件，成功后不再依赖 `ImageSelection` 的存活。第一版允许复制文件以简化所有权，后续优化不能改变语义。
- 文件导出在模块私有路径完成，成功前不暴露半文件。失败或取消删除未交付文件。
- 导出接口负责转换，不上传。聊天发送任务读取 `ImageFile.LocalPath`，发送结束或放弃时释放它。
- 需要跨应用重启恢复上传时，发送模块必须先把文件复制到自己管理的持久目录，并保存任务记录；框架临时文件不承担持久任务存储。

## 5. 生命周期、取消与并发

### 5.1 资源所有者

| 场景 | 所有者 | 释放时机 |
| --- | --- | --- |
| 头像预览 | 面板 / `OpenScope` | 替换图片或面板关闭 |
| 聊天附件确认 | 附件编辑界面 | 移除附件或放弃编辑 |
| 聊天上传文件 | 发送任务 | 上传结束、最终放弃或显式清理 |
| 相册列表缩略图 | 列表单元或有界缓存 | 单元换图、回收或缓存淘汰 |

纹理所有者只有一个。UI 在释放纹理前先清空相应 Image / RawImage 的引用；业务不能再单独 Destroy 由 `ImageTexture` 管理的纹理或 Sprite。

把结果登记到 `OpenScope` 前，须确认本次打开的 Token 尚未取消、作用域仍有效；登记失败时由当前调用释放尚未移交的结果。异步返回后不能直接使用一个可能已被重新打开替换的面板作用域。

资源释放与操作取消分开：释放来源对象后拒绝新的读取，已经受理的读取通过内部短期租约保证来源存活，结束后释放租约。需要中止读取时使用该操作的 Token，不能因一个调用方释放结果而删除其他在途读取正在使用的文件。

### 5.2 系统窗口互斥

同一时间只允许一个原生图片选择窗口。再次调用报告 `PickerBusy`，不排队、不合并、不复用第一次的选择结果。此限制只保护原生窗口呈现，不阻塞独立文件导出、预览或目录查询。

分别记录：

- 原生窗口：`Idle → Presenting → Dismissing → Idle`。
- 请求任务：`Pending → Importing → Succeeded / Canceled / Failed`。

选择窗口关闭后，上一批文件仍可能在导入，此时不必继续占用“窗口忙碌”标记；是否允许下一次打开由实际原生窗口状态决定。

### 5.3 取消与迟到回调

- 用户在系统窗口返回 / 取消，以及调用方 Token 取消，均表现为任务取消。
- Token 取消后停止或丢弃尚未完成的工作，清理未交付资源。可关闭原生窗口时执行关闭；无法立即关闭时，窗口忙碌保持到真实关闭。
- 请求 ID 必须唯一且包含运行会话标识；Unity 编辑器停止播放 / 重新进入后，旧回调不能命中新请求。
- 每个请求只能完成一次。迟到成功不能覆盖取消或失败，重复回调不能再次交付或重复释放。
- 不以 `OnApplicationFocus(true)` 单独推断取消：授权窗口、云端下载和系统界面切换都可能改变焦点。
- Activity 重建时保留可恢复的请求关联；确实无法恢复时明确结束请求，不能永久挂起。整个应用进程被系统终止后，不承诺恢复旧的 UniTask。
- 一次文件解码失败仅结束该操作；没有证据表明共享桥接状态损坏时，不封锁后续独立操作。

### 5.4 临时文件与退出

使用模块独占的会话目录。正常路径由各资源句柄清理；应用下次启动时清理确认属于旧会话的遗留文件。不得扫描删除用户相册或通用缓存目录。

模块内部运行器在退出时终结尚未完成的等待并尝试清理自有资源。退出回调无法保证在进程被杀时执行，因此需要上述旧会话清理。

同步 `Dispose` 在主线程执行并声明幂等。首次清理失败要传播，后续 Dispose 不自动重试。发生主错误时，清理错误单独记录，保留主异常。

## 6. 错误与权限模型

普通 C# 参数错误使用原有异常类型，不统一包装。原生操作失败使用 `GalleryException`，包含稳定错误码、平台原始错误域 / 代码 / 信息和请求 ID；不把图片内容或完整私人路径写入默认日志。

| 情况 | 对外行为 |
| --- | --- |
| 无效数量、尺寸、质量、游标 | 参数错误，能预先发现的在副作用前拒绝 |
| 已释放的结果被重新使用 | `ObjectDisposedException` |
| 系统或指定能力不支持 | `PlatformNotSupportedException` 或明确定义的能力不支持错误 |
| 用户取消 / Token 取消 | 取消状态 |
| 原生选择器已打开 | `PickerBusy` |
| 实际选中数量超限 | `SelectionLimitExceeded` |
| 必需权限被拒绝或撤销 | `PermissionDenied` |
| 来源图片已删除 / 无法再访问 | `SourceUnavailable` |
| 格式无法解码 | `UnsupportedFormat` |
| 读取、下载、复制、磁盘空间不足 | 保留原生原因的读取 / 写入失败 |
| 成功枚举一个空目录 / 空相册 | 空页，属于正常成功 |

系统选图成功时必须至少一张图片，不能用空集合代表权限拒绝或取消。单独的权限查询 / 请求接口以访问状态为返回值，可以正常返回 Denied；它承诺报告授权结果，不承诺一定拿到授权。真正需要权限的数据操作在拒绝时失败。

## 7. Android 实现步骤

1. 建立 Java 桥接及独立的非导出宿主 Activity，避免修改 Unity 主 Activity；验证 Manifest 合并、返回结果、配置变化和销毁路径。记录宿主使用 Activity 还是 GameActivity，并验证对应 Unity 配置。
2. API 33+ 使用 `ACTION_PICK_IMAGES`；多选设置平台允许的数量。API 25–32 使用 `ACTION_OPEN_DOCUMENT` + 图片 MIME + 明确的多选标记。
3. 所有返回资源通过 URI 和 ContentResolver 读取。禁止通过 `_data` 列或字符串裁剪“还原真实路径”。
4. 将结果流式复制到唯一暂存文件，验证关闭流与失败清理；第一阶段不申请照片库或全部文件访问权限。
5. API 28+ 评估 ImageDecoder；API 25–27 使用 BitmapFactory 采样解码。方向与镜像信息需覆盖 EXIF 的全部有效方向，不能只处理 90 度旋转。
6. 原生线程回调带请求 ID；通过主线程调度完成 Unity 对象创建与任务交付。回调数据使用结构化序列化，文件名不能用未经转义的分隔符拼接。
7. 配置必要的 Java 保留规则，验证 R8 / 混淆开启的发布构建中桥接入口仍可调用。
8. 第三阶段才加入 MediaStore 查询和照片读取权限：API 25–32、33、34+ 分别处理旧存储读取、图片媒体读取和部分照片访问语义，并结合实际 Target SDK 验证。
9. 相册读取不申请 `MANAGE_EXTERNAL_STORAGE`。系统选择器成功不代表整个 MediaStore 已获授权。

权限清单以启用的功能为条件：只使用系统选图的构建不得因为代码中包含相册查询就无条件加入广泛读取权限。

## 8. iOS 实现步骤

1. `.mm` 桥接通过稳定的 C ABI 暴露接口，使用 `[DllImport("__Internal")]` 调用；明确跨边界字符串 / 缓冲区的复制和释放责任，并验证 IL2CPP AOT 回调。
2. 在主线程获取有效呈现控制器，配置 PHPicker 的图片过滤、单选 / 多选上限和表示偏好。已有不兼容模态呈现时明确报忙碌，不能覆盖现有界面。
3. 从 NSItemProvider 获取文件表示，在有效期内复制到模块暂存目录；保留格式信息，不只复制临时路径字符串。
4. 使用 ImageIO 缩略图解码路径控制尺寸、处理方向；HEIC 是否支持以实际设备及系统能力为准。
5. 用户取消、系统错误、加载失败和 Token 取消分别映射；native 下载可取消时发送取消请求，迟到回调仍需释放资源。
6. 构建处理器链接实际使用的 PhotosUI、ImageIO 等系统框架，并保证 availability 检查；第三阶段 PhotoKit 接入再加入 Photos 的查询能力和必要配置。
7. 第一阶段仅用 PHPicker，不为它无条件申请 PhotoKit 全库读取授权。
8. 第三阶段使用 PhotoKit 的 read-write 访问查询 / 请求接口，处理 Authorized、Limited、Denied、Restricted、NotDetermined；请求前由构建配置提供真实的 `NSPhotoLibraryUsageDescription`，缺失时构建明确报错。
9. Limited 状态下只展示可访问内容，并提供用户主动调整授权照片的入口；不会默认反复弹出授权界面。

不承诺读取整个 Live Photo 的成套资源；本模块首轮只处理静态图片表示。系统资源标识也不是可直接上传的本地路径。

## 9. 第二阶段：普通目录浏览

拟定入口：

```csharp
UniTask<ImagePage> GameImageDirectory.QueryAsync(
    ImageDirectoryQuery query,
    CancellationToken cancellationToken = default);
```

`ImageDirectoryQuery` 明确包含绝对根路径、是否递归、允许的扩展名、页大小和后续游标。默认不递归，默认页大小 60，允许 1–200；非法值拒绝而不截断。

实施规则：

- 先支持 Editor、桌面和移动端应用自己的可访问普通目录。`StreamingAssets` 在 Android 等平台可能不是普通文件目录，不纳入本接口的通用承诺。
- 只枚举元数据，不读取每个文件的完整内容；用扩展名做候选筛选，真正读取时再验证格式。
- 第一版可建立一次元数据快照后按规范化相对路径稳定排序和分页，必须说明首次查询仍可能遍历整个目录；不能把分页返回宣传为底层扫描量恒定。
- 不跟随符号链接目录，避免环与越过指定目录边界；根目录中合法的普通文件仍正常枚举。
- 不存在、无权限和枚举中途失败均可观察，不默默跳过失败子目录后报告“全部成功”。空目录正常返回空页。
- 文件列表是查询时快照；读取前文件被删除、替换或权限变化时，报告实际失败，不保证引用对应的内容永久不变。
- 游标只属于本次查询快照和相同查询条件；快照释放或条件改变后不得继续使用。

验收样本包括空目录、多层目录、中文与特殊字符文件名、伪装扩展名、无权限子目录、取消、扫描后删除和大量文件。

## 10. 第三阶段：自定义相册浏览

拟定接口组：

```text
GameGallery.GetLibraryAccessAsync()
GameGallery.RequestLibraryAccessAsync()
GameGallery.QueryAlbumsAsync(query, token)
GameGallery.QueryImagesAsync(query, token)
GameImageReader.LoadThumbnailAsync(image, options, token)
```

必须实现：

1. 权限状态查询与用户主动发起的权限请求分开；只有相册浏览需要时才请求。
2. 定义统一的逻辑相册摘要：来源 ID、显示名、可选数量。Android 的 bucket 和 iOS 的 collection 不保证一一等价，数量未知时不伪造。
3. 图片默认按创建时间降序、来源 ID 作为稳定次级排序；缺失时间的排序规则固定并写入实际文档。
4. 分页游标绑定来源、相册、排序、访问范围和查询代次。照片库变化或授权变化使旧代次失效，后续查询明确要求刷新，不静默把新旧结果拼成完整列表。
5. Android 使用 MediaStore 并验证各版本分页支持，iOS 使用 PhotoKit 查询结果；如果某平台需要先建立元数据索引，明确记录其首次查询成本。
6. 原生变化通知触发图库索引按声明的策略核对，再向业务发布变化；无法取得可靠增量时明确核对元数据。核对失败向调用方传播，不自动重试。具体流程见 [长期实施计划](GalleryLongTermBackupPlan.md)。
7. 在现有循环列表中按可见范围请求缩略图，单元重绑后旧请求不能写回。缩略图与预览使用独立的尺寸选项。
8. 使用有界缓存，键包含来源、资源版本、目标尺寸和方向处理方式。本轮空闲缩略图缓存初始预算 32 MiB，图片处理维持现有并发 1；在用、在途和待销毁资源分别计量，具体租约与请求合并规则见长期实施计划。
9. 缓存只淘汰未被使用的条目；屏幕上仍被持有的纹理与缓存预算分别计量，不声称缓存上限就是整个图片模块内存上限。
10. 云端资源允许显式下载策略。缩略图可用不代表完整文件已经在本地；离线读取失败必须传给调用方。

此阶段的相册引用不拥有用户照片；释放列表或查询结果绝不能删除原始资源。平台资源失效时可观察地失败。

## 11. 第四阶段：外部目录授权

独立于普通字符串路径接口实施：Android 使用 Storage Access Framework 目录树 URI；iOS 使用文档选择与 security-scoped URL / 必要书签。先做平台能力验证，再确定公开 `ImageDirectoryHandle` 契约。

必须定义授权范围、有效期、应用重启后的可恢复性、授权撤销、目录提供者不支持某项能力时的失败，以及访问句柄的释放。不能把授权句柄转换成猜测的文件系统路径，也不能向上层保证访问任意目录。

只有业务确实需要访问外部目录时才进入该阶段；第二阶段完成不等于已完成外部目录授权。

## 12. 第五阶段：图片与相机照片备份

### 12.1 功能范围与默认行为

“相机备份”指备份手机拍摄后已经保存的静态照片，不包含调用摄像头、录像或实时视频上传，因此不额外申请摄像头权限。

| 模式 | 来源与行为 | 依赖 |
| --- | --- | --- |
| 手动备份 | 用户通过系统选择器选图并提交备份 | 第一阶段，不要求全库授权 |
| 指定范围备份 | 用户选择可访问的相册或目录，执行一次扫描并备份 | 相册第三阶段；普通目录第二阶段；外部目录第四阶段 |
| 自动备份 | 用户主动开启后，在允许的执行机会中扫描所选范围，发现新增 / 变化的图片并入队 | 对应来源读取权限、增量发现与平台调度 |

默认自动备份关闭。开启流程必须明确账号、服务器、来源范围、是否包含现有照片，以及网络策略；首次启用让用户选择“包含现有照片”或“从本次建立的基线之后开始”。建立基线时仍需处理扫描期间的变化，不能仅比较照片拍摄时间。

默认只通过符合 Wi-Fi 策略的网络上传，蜂窝网络须由用户主动允许；实现时分别记录 Wi-Fi 与系统的计费网络状态，不能把“非计费网络”等同于 Wi-Fi。运行中条件不再满足时停止提交新传输，并请求暂停在途传输；不承诺网络切换瞬间零流量。

相机照片的范围按平台查询能力与用户选择确定。Android 的 DCIM / Camera 可作为候选目录，不能硬编码成所有设备的唯一来源；iOS 不承诺能无歧义区分全部“本机相机拍摄”照片，无法可靠识别时要求用户明确选择相册 / 范围，不能自动扩大到整个照片库。

只做单向备份：手机照片被删除不触发服务器删除，服务器存在副本也不触发手机删除。照片被编辑后的内容按新版本记录，默认保留已确认的旧版本；不设计双向冲突合并。

### 12.2 权限、增量发现与备份身份

- 系统选图提供的是选中内容，不赋予访问未来新增照片的权限。持续发现照片必须使用对应照片库授权或有效的目录授权。
- 访问范围可能为全部或部分；界面显示真实范围与扫描状态。部分授权时不能显示“整个相册已备份”。权限拒绝 / 撤销后停止相应来源扫描并标记需处理，不循环弹出请求。
- 使用来源 ID、来源版本 / 变更信息进行候选发现；照片导入时间、拍摄时间和修改时间不同，不能只用“上次备份时间”过滤新照片。
- 系统变化通知只用来触发可执行时的扫描；应用恢复、通知缺失或数据代次失效时进行重新对账。第一版允许分批全量元数据对账，记录开销，不声称已有可靠的系统增量游标。
- 自动扫描属于用户开启的备份策略，不改变第三阶段查询 API 不自动重试的契约。扫描失败保留错误，成功处理的游标 / 页和任务登记必须事务性协调，不能先推进进度再漏记任务。
- 对准备好的不可变上传文件计算 SHA-256 和字节数。来源标识用于追踪，内容指纹用于校验和去重，两者不能互相替代。读取发生变化时，以实际暂存字节为一次上传版本，再重新检查来源变化。
- 去重限定在服务器与账号范围内。同一内容可关联多个来源记录；不能因为存储文件去重而丢失不同相册、文件名或来源版本的记录。
- 图片备份默认保留系统 / 提供者交付的字节，沿用第 4 节的“原图”限制；自动备份不得复用聊天缩图策略而无提示地降低画质。视频、Live Photo 配套视频和 RAW 成套资源不在首轮完整性承诺内。

### 12.3 持久任务与文件归属

处理流程：发现来源 → 登记候选 → 准备不可变文件 → 计算指纹 → 建立或恢复上传会话 → 上传 → 服务端校验提交 → 本地记录完成 → 清理上传暂存文件。

备份队列及其文件位于模块专属的持久目录，不使用第 5 节的会话临时目录；启动时清理旧会话文件不得删除备份任务数据。只为有限数量的候选准备完整文件，并配置暂存磁盘预算及单文件限制，避免扫描整个图库时复制全部原图。本轮不扩大现有上传并发：前台与 Android 为 1，iOS 每个网络会话同主机连接上限为 2。

手动选择的文件具有选择结果有效期限制：`EnqueueAsync` 成功前，必须已经把这批文件及任务记录可靠地移交至备份持久存储。空间不足则明确失败，清理未提交文件；不能先报告已入队、随后随面板关闭丢失文件。该次接收采用整批提交，自动扫描则按图片独立登记以隔离单图失败。

拟定公开操作：

```text
GameImageBackup.EnqueueAsync(selection, options, token)  持久接收，返回任务 ID 集合
GameImageBackup.ConfigureAutomaticAsync(policy, token)  保存范围与明确启用状态
GameImageBackup.ScanAsync(source, token)                请求本次扫描，不保证立即上传
GameImageBackup.GetStatusAsync(query, token)            查询持久状态与进度
GameImageBackup.PauseAsync(scope, token)                停止调度并协调在途传输
GameImageBackup.ResumeAsync(scope, token)               重新按策略调度
GameImageBackup.CancelAsync(taskId, token)              取消任务，不删除已备份副本
GameImageBackup.RetryAsync(taskId, token)               用户明确重试失败任务
```

调用 Token 只控制当前 API 的等待或未提交接收过程；持久入队完成后，面板 Token 不再取消备份任务。提交前取消不接收任务；提交已发生就按已确定的提交结果返回任务 ID，不事后伪装成未入队。UI 需显示的传输进度以服务端确认字节与明确的阶段为准，进度 100% 仍需等待提交确认。

持久记录至少包含：任务 ID、批次 ID、账号与服务器标识、来源范围及版本、准备文件位置、实际格式 / 大小 / 指纹、上传会话、已确认分片或偏移、幂等键、状态、尝试次数、下次执行时间、最后错误、原生任务关联和任务代次。

正常状态为 `Queued → Preparing → Ready → Uploading → Verifying → Completed`；还需独立表达策略等待、`Paused`、`RetryScheduled`、`NeedsAttention`、`Failed`、`Canceled`。等待 Wi-Fi / 系统调度不是上传失败，来源失效不是用户取消。

当前源码采用持久交接意图 + 原生唯一执行者：C# 任务记录包含 `nativeOwned`，原生独占自己的执行记录，C# 对账完成后才能回收文件；恢复前核对系统任务。业务队列不直接接受旧原生回调，旧任务释放前不能重试。后续 SQLite 方案已细化到 [长期实施计划](GalleryLongTermBackupPlan.md)：一份共享原生 BackupRepository 持有 catalog，统一保存业务任务和系统执行记录；C# 与平台回调通过同一命令接口更新，完成结果、确认回执和清理意图一次事务提交。它依赖 Runtime/Sqlite 的统一核心，平台不再各写一套 SQL。此方案尚未实现，不能视为当前交付；统一核心构建、无 Unity 启动和交接验证是进入存储改造的前置门槛。

暂停 / 取消先持久记录意图，再协调原生任务停止；迟到回调需按任务代次处理。服务器可能已收到文件甚至完成提交，取消不代表撤回远端内容。未确定提交结果的任务保留待核对信息，不能一边删除全部身份记录一边报告“服务器没有副本”。清理本地文件须等在途传输不再使用它。

退出账号时停用该账号的自动策略并停止其传输，原任务仍绑定原账号；切换账号不得接管旧任务或复用其凭据。凭据从系统安全存储获取，不写入普通任务字段。权限撤销或范围缩小时，第一版暂停相关来源尚未完成的任务，已经准备的文件也不继续自动上传；重新确认范围后由用户显式恢复或取消。

### 12.4 服务端契约与成功条件

目前未提供现有服务端地址、认证方式或上传协议，因此本方案不假设已有可用接口。B0 必须确认复用现有服务还是新增最小备份服务，记录接口契约；客户端演示使用模拟服务不能视为完成服务器备份。

| 接口职责 | 请求 / 返回至少包含 | 必须保证 |
| --- | --- | --- |
| 认证与能力查询 | 账号、协议版本、格式 / 文件大小限制、分片规则 | HTTPS，服务端校验账号归属；客户端明确处理不支持能力 |
| 创建 / 查找上传会话 | 幂等键、内容指纹、字节数、来源版本；返回会话及已确认内容 | 重复请求安全；去重以账号授权为边界 |
| 上传数据与查询进度 | 会话 ID、分片或偏移、数据校验；返回确认位置 | 中断后可查询真实进度；不能只信客户端发送字节计数 |
| 提交备份 | 会话与完整校验信息；返回备份 ID、实际大小与指纹 | 完整性校验与账号备份记录落库后才确认；重复提交不重复建记录 |
| 查询备份结果 | 账号、幂等键 / 会话 / 备份 ID | 可判定响应丢失前是否已提交，支持重启对账 |
| 取回验证 | 备份 ID；返回有授权的下载方式 | 真正读回文件并校验内容，证明可恢复性 |
| 放弃未完成会话 | 会话 ID | 仅回收未提交上传；不删除已确认备份；服务端清理过期分片 |

初版使用服务端支持的可恢复上传协议，具体选择由 B0 固定；不能把一次普通 PUT 自称支持断点续传。若服务端只支持整文件重新上传，必须明确该限制并重新约定验收范围。

只有服务端完成完整性校验并返回可查询的持久备份记录，客户端才标记 `Completed`。网络发送完毕、对象存储上传成功但备份记录未提交、客户端进入后台，都不能作为完成条件。首次闭环验收必须下载备份并核对 SHA-256；这属于备份可恢复性验证，不要求本期开发完整的恢复图库 UI。

### 12.5 失败、重试与恢复

图片获取和单次上传适配器仍逐次传播失败，不内部吞错重试。用户启用备份策略时，可明确启用有限的传输重试：由备份调度器记录失败尝试，再持久安排下一次尝试；不是把原失败改写为成功，也不改变 UIFrame 其他模块的错误契约。

- 默认策略建议最多自动重试 5 次，基础等待为 5 秒、30 秒、2 分钟、10 分钟、30 分钟，附加随机抖动；服务端合法的 `Retry-After` 作为最早可重试时间约束，后台系统可进一步延后。配置必须写入策略记录并对用户可见。
- 仅连接中断、超时、HTTP 408 / 429 及接口约定的临时服务错误可进入重试。等待网络、用户暂停和系统未调度不消耗失败次数。
- 凭据过期进入待认证状态，权限拒绝、来源丢失、配额 / 空间不足和格式不支持进入需处理或失败状态，不能循环重试。凭据正常刷新由认证服务负责，其失败仍需可观察。
- 校验不一致、协议不兼容和程序错误直接失败并保留诊断信息，不自动用新幂等键重新提交绕过问题。
- 超时和响应丢失意味着结果可能未知；下一次尝试先查询会话 / 备份状态，再决定补传或结束，复用原幂等身份。
- 达到次数上限后失败并等待用户处理；单图失败不阻塞其他独立图片。持久仓库损坏等共享故障才停止该仓库的调度，并保留可恢复数据。
- 进程退出恢复先对账服务端提交与原生任务状态；已确认完成但本地未落库的任务应恢复为已完成，不重新建立副本。

### 12.6 Android / iOS 后台执行

后台发现新照片与后台传输已准备文件是两种能力，分别报告支持状态。后台执行不能依赖 Unity Update、MonoBehaviour 或持续存活的 C# 协程。

| 平台 | 实施路线 | 不承诺的行为 |
| --- | --- | --- |
| Android | 本阶段使用系统 JobScheduler 持久传输已准备文件、网络约束与系统重调度；后台发现仍待实现；长任务按目标 SDK 评估用户可见前台服务及类型 / 时限要求 | 不绕过省电策略；强制停止后不保证继续；不保证固定扫描频率 |
| iOS | 使用原生 background URLSession 传输已准备的文件；按能力配置 BGTaskScheduler 执行机会中的发现 / 整理，并实现 expiration 收尾 | 不保证即时唤醒、固定周期、用户强制退出后继续；Unity 未运行时不能依赖 C# 回调处理 |

Android 第一阶段避免 AndroidX 的决定仍适用于图片获取；B5 若选用 WorkManager，再把 AndroidX 作为备份的显式可选依赖加入并验证冲突，不提前让所有相册使用者承担该依赖。

iOS 上传使用系统可访问且在任务存活期间保留的文件。若服务端采用分片上传，每个分片必须满足文件上传方式和独立校验要求；不得假定后台 URLSession 会替任意服务端协议自动续传。原生层持久记录后台结果，Unity 恢复时读取；系统回调的 completion handler 必须及时完成。

原生调度器需复用账号、网络、暂停、任务认领与重试策略，系统重调度不能额外创建一套无限重试。系统唤醒、网络变化或重新进入应用只能在已启用策略内安排工作，不能恢复用户已关闭的自动备份。

界面报告“已备份数量、等待条件、正在处理、需处理 / 失败、最近一次扫描时间及覆盖范围”，不把尚未执行的后台任务显示为“全部已备份”。后台权限、系统设置、部署版本和实际执行限制均进入真机验收记录。

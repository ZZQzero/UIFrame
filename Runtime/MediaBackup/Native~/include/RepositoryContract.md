# Shared BackupRepository contract

ABI 4 (`ufb_status`: 284 bytes), catalog schema 3, SQLite core ABI 3. The only network protocol is v2. There are no schema migrations or old upload/session commands. SQL and business transitions live in `repository.cpp` and `protocol.cpp`; adapters perform scheduling, HTTP, protected storage and actual release.

A store is `<private root>/<SHA256(normalized server + newline + account)>/catalog.sqlite`. Its random source_namespace is distinct from the store ID, so local gallery IDs from different installations do not collide. Native existing-open reads persisted server/account without Unity. Android uses no-backup files; iOS uses Application Support, excluded from iCloud backup. C# exclusively owns preparation; native attachments retain their own repository lifetime.

Wire input is a uint32 count followed by tagged SQLite values; output is bounded tables. Commands run on a worker, with at most 1 MiB input/output, 200 rows and 16 admitted calls process-wide. Registration admits at most 128 unfinished members, one actual unsealed producer and 64 sealed photos. The default staging budget is 1 GiB and the maximum photo size is 512 MiB, with 16 MiB filesystem headroom. Plan/Query/Cancel have at most 32 items, 256 KiB requests, 512 KiB responses and 8 KiB upload descriptions. Control files have a separate 8 MiB budget. A control list excludes request bodies; the executor streams its durable file.

| Command | Contract |
| --- | --- |
| Prepare (2) | Prepare(operationId, preparer, now, count, taskId/source/version/name/mime..., scopeIdOrEmpty, epochOrZero) registers fixed members and their immutable control scope before file I/O. It checks global pause, the 128-member bound and enabled/current scope; scoped discoveries are claimed in the same transaction. All source leases must already be held. Initial file occupancy is zero; only TryPrepare reserves capacity. The old per-item reservation field is not accepted. Metadata is nonempty and rejects control characters; source/version/name are at most 1024 UTF-8 bytes, MIME 128. |
| TryPrepare (77) | Takes taskId/preparer/required/maximum/budget/now. Checks scope epoch, pause, stop intent, one active producer, 64 sealed files, staging and disk capacity, then atomically reserves and marks preparation_started. Returns admitted/reasons/required_bytes/available_bytes/occupied_bytes/staged_count. Reasons: 1 staging budget, 2 disk space, 4 file window, 8 global pause, 16 stop intent, 32 scope/member ineligibility, 64 producer occupied. Capacity refusal is a read-only outcome, not a failed attempt. |
| PreparationEligibility (78), StopPreparation (79) | Eligibility(taskId) returns state, desired_action, stop_requested, paused and scope_valid. StopPreparation(operationId) persists stop intent for unaccepted members; adapters must await actual producers before FailItem or cleanup. Waiting on a managed submission never cancels its preparation. |
| Seal (3), AcceptItem (96), FailItem (97) | Seal(taskId, preparer, bytes, sha256, mime, budget, now) requires prior reservation and verifies durable file size within that reservation before publishing it. AcceptItem(taskId, preparer, now) atomically records preparation_accepted for a sealed photo, returning accepted=0 if pause/stop/scope eligibility was lost; invalid state/owner remains an error. FailItem(taskId, preparer, error, now) isolates an unaccepted source failure and its cleanup. Scope-invalid candidates return to pending for explicit scope confirmation; independent source failures retain disposition 4. Removed members and shared confirmations are not overwritten. Other accepted members survive. |
| RecoverPreparations (55) | Recovery fails only interrupted, unaccepted preparation members; previously accepted members and their files remain owned. Preparation failures retain queryable task results. Acceptance and failure always use the per-item commands. |
| Submission (98) | Returns at most 32 fixed members in ordinal order, including preparation_started, accepted/system-scheduled phase and errors. Pruned task details set details_expired; callers must not invent a task state. Minimal operation membership remains queryable. |
| Claim (9), Handoff (74) | Claim(taskId, executor, wifiOnly, now) atomically assigns a generation to an eligible queued task. Lost eligibility returns an empty table. Handoff(taskId, generation, protectedCredentialReference) transfers durable local facts; no server request is a precondition. |
| Attempts (23), Ready (62) | Attempts takes afterSequence/executor/pageSize and starts from the unreleased-attempt partial index. Ready(afterSequence, upperSequence, pageSize) returns queued foreground admissions. No historical session ID, retry timer or content-key lease is retained. |
| ControlCreate (80) | Takes requestId/executor/now/allowFuture/flush. Persists exact body and fixed membership from one scope/epoch before any file/network effect. The ready control quota is one per executor/repository; a single future Query has its own queued slot. Alternates due Query and Plan, with cancel priority. Plan aggregates for 250 ms unless full or explicitly flushed. |
| ControlSeal (81), Submitted (82), Start (83) | Seal(requestId) durably writes the registered file. Submitted(requestId, systemId) records OS ownership before execution; Start(requestId) records active execution. Submitted/Start return admitted and recheck Plan scope and all non-Cancel pause/member constraints. Refusal must be settled as paused; an already-created OS task is canceled and released only after its completion. HTTP is outside the SQL transaction. |
| ControlValidate (84), Apply (85) | Validate(requestId, response) checks the whole envelope, account, exact membership, every current generation, nested content/source identity and upload policy. Returns only upload descriptions requiring protected storage. Apply(requestId, response, now, count, taskId/protectedReference...) repeats validation, then atomically commits each independent result with its applied marker. Invalid whole responses cannot publish earlier good members. Replay of already-applied members is idempotent. |
| ControlFail (86), Recover (88), Release (87) | Fail/Recover(requestId, error, now, paused) preserves unknown results or explicit pause; it never fabricates cancellation or retries the request. Release(requestId) is legal after its outcome and only after the platform has observed actual HTTP/system completion. Receipt application alone does not release the file. |
| Control (104), Controls (89) | Read one request by ID, or at most 32 active requests by executor/afterId. The list contains metadata and one protected API reference, not full bodies or secrets. |
| Uploads (90), UploadStart (91) | Uploads(executor, afterTaskId) selects independent eligible photos. UploadStart(taskId, generation, systemId, now) returns started=0 for lost pause/expiry/admission eligibility; it never starts a duplicate transfer. A successful claim owns the stream and description. |
| UploadEnd (92), UploadRelease (93), UploadReject (106) | End(taskId, generation, outcome, error, now): 0 unknown, 1 transport success, 2 paused. Success enters confirmation, frees the execution slot and sets first check to now + 1 s; no receipt is inferred from PUT. Release(taskId, generation, now) follows actual stream/OS and protected-description release; releasing an unused expired description atomically exposes Plan, without requiring another executor wake. Reject(taskId, generation, error, now) isolates a local failure before creating any system task; the remote result remains unknown. |
| ProtocolActions (94), Wake (105), Configure (99) | Apply idle pause/deadline transitions; select the next aggregation/check time, including deadlines of bound Query controls (integer zero when none); configure explicit development HTTP and automatic/user-initiated mode. Expired descriptions must be released before another Plan. The 256th Pending response ends automatic confirmation. Pending follows server nextCheckAt; a time at or beyond the 24-hour deadline ends automatic work instead of querying early. Controls expose derived deadline_utc (earliest member deadline for Query, zero for other kinds). Executors cancel expired requests and record actual release only when their owner has finished. A shared Query stops at its earliest member deadline; unresolved members retain unknown outcomes. OS wake is not guaranteed at the wall-clock deadline. Valid late Confirmed/Canceled/Rejected results remain authoritative; expired Pending/UploadRequired cannot authorize further work. |
| SystemScheduled (95) | Record executor/repository scheduling only after the responsible OS job/session request (or desktop driver) is actually accepted. It describes admission, never a confirmed backup. |
| ProtocolReconcile (101), Resume (103), Release (102) | Reconcile(taskId, now, cancel, newCredentialReference) requires previous uploads, controls and protected credentials to be released, then explicitly resumes an unknown remote result using Query/Cancel at the same generation. A saved cancel intent is retained even when cancel=false; reconciliation never withdraws cancellation. Resume(taskId, newCredentialReference, now) reauthorizes a released paused task. Release(taskId, generation) acknowledges actual API-credential deletion only after uploads and controls released. |
| Action (14), Pause (15) | Per-task intent and global pause are independent. Global pause atomically stops all unaccepted preparations; unpausing cannot revive them. Retry accepts only a definite failure retaining a valid staged file; unknown results require Reconcile, failed preparation requires a new source submission. A shared in-flight control retains ownership until its completion; requesting pause does not invent release. |
| Operation / Select / Apply (40–42) | Durable ID, fingerprint and submission upper bound. Selection pages ≤128, application pages ≤32. WaitingForRelease is nonterminal. IDs never replay. History removal skips a task with failed/unreleased control cleanup rather than failing unrelated items. |
| Cleanup (18/19/21), Failures (76) | Recheck all ownership before deleting a photo or its export directory. Code 1001 means a filesystem failure was durably isolated; other files continue. Failed cleanup is never automatically retried. Read failures by file-ID cursor, including abandoned files whose task_id is null. Explicit Retry chooses one file. |
| ProtocolCleanup (100), ControlCleanupFailures (107), ControlCleanupRetry (108) | Cleanup(now, limit≤64) removes released control files; isolated failures remain queryable. Clear the body after physical deletion, retain small diagnostic rows for 30 days, and prune at most limit old requests and their bounded members per call. Failures(afterId, pageSize≤200) is read-only. Retry(requestId, now) retries exactly that failed file and throws code 1001 if it fails again. |
| Scope / scan / disposition (30–36,69–73), ConfirmScope (109) | Tasks keep one scope_id/scope_epoch; discovery and receipt sharing never transfers task control. Rejoining sources may associate only with preparation_accepted tasks; sealing a subsequently failed/canceled preparation does not establish acceptance. SuspendScope first closes admission and advances the epoch, then records pause intents only for owned tasks in pages of 32. Routine reconciliation uses enabled without revoking retained tasks; requires_confirmation is separate. ConfirmScope clears that flag after old preparation owners ended; it never upgrades old task epochs. Explicit task Resume/Retry requires an enabled confirmed scope and adopts its current epoch. Baseline reset advances the epoch and retains receipts and accepted tasks. |
| History/metadata pruning (50–52,67–68,72) | Preserve receipts, source dispositions and minimal operation identities. Select indexed bounded pages. Receipt and source relationships are independent of task history. |

Task states: 0 queued, 1 uploading/registration, 2 confirming, 3 completed, 4 paused, 6 needs attention, 7 failed, 8 canceled, 9 preparing. Protocol phases: 0 Plan, 1 file PUT, 2 Query, 3 terminal. Canceled and Completed require authoritative protocol results where an accepted remote attempt exists. A canceled attempt's old upload authorization cannot publish a new record.

Pausing a Plan before system submission preserves registration; pausing a future Query preserves its next-check time. Global pause does not interrupt a Cancel control. A saved cancel intent can advance once after an interrupted Plan/Upload/Query, but a failed Cancel is terminal NeedsAttention and is never automatically sent again. After actual release, explicit Reconcile may continue that cancellation. Terminal credentials are released even when the stored desired action is Cancel.

Protected descriptions and credentials are never plaintext SQL. Android stores AES/GCM ciphertext protected by AndroidKeyStore. iOS stores Keychain references with after-first-unlock access; startup compares this service's live credential attributes against exact persisted attempts to remove interrupted handoff orphans. Desktop references are process-bound and require explicit reconciliation after process death.

The managed coordinator returns a registered handle immediately, holds every source lease until actual per-member completion and serializes file preparation. Capacity is event-driven with a bounded periodic check. Source failures are isolated, while unsafe shared repository state fences subsequent preparation until explicit close/reopen. Automatic discovery registers at most 128 members per pass and never waits for their preparation. Desktop Plan flushing follows actual preparation completion, not registration completion. A scheduling failure ends its preparation batch and is not retried by finalization.

Any unknown database commit stops dependent repository execution. Adapters must retain potentially transferred resources and the original error, then explicitly recover after positively observing prior owners ended. An isolated file error does not invalidate the repository. Shutdown attempts every owned cleanup and reports the primary error; subsequent cleanup errors are separate.

Executable evidence is in repository_tests.cpp, protocol_tests.py, admission_tests.py, process_windows.py (48 killed-process windows), reconciliation_lifecycle.py, scope_reconciliation.py and the Android production-JNI binding test. The host tests do not prove phone OS scheduling, lock-screen behavior or force-stop guarantees.

# Shared BackupRepository contract

ABI 1 (`ufb_status`: 284 bytes), SQLite core ABI 3. `ufbackup_call` is blocking and must run on a platform worker; it never calls user code. The library links the existing engine and exports no SQLite engine symbols. SQL and state transitions exist only in `repository.cpp`.

A store is `<private root>/<SHA256(normalized server + newline + account)>/catalog.sqlite`. Android uses `getNoBackupFilesDir()/UIFrameBackup`; iOS uses Application Support/UIFrameBackup, excluded from iCloud backup. Native existing-open reads persisted server/account without Unity. C# holds the exclusive preparation attachment; platform attachments independently retain the catalog for background work.

Input is a little-endian uint32 count followed by tagged values from the SQLite wire format. Output uses its table format. All strings are UTF-8. Maximum 1 MiB per command/result, 200 returned rows, 16 admitted commands process-wide, 64 attachments. C# bounds buffer admission before allocating the output page. These are request limits, not total process-memory guarantees.

| Operation | Atomic result / ownership |
| --- | --- |
| Prepare (2), ReservePayload (65), Seal (3), Accept (4) | Preparation ID is known before submission; 1–32 items. Copy reservation is durable before file creation. The copier hashes the file. Seal opens and validates the regular non-link file, checks its size, and flushes it before starting the database transaction (fsync plus F_FULLFSYNC on Apple, FlushFileBuffers on Windows). POSIX also syncs the payload and store directories. Accept atomically publishes the complete batch; a durability error leaves preparation unaccepted. |
| Preparation (64) | Returns durable header and original task IDs independently of task-history retention. Unknown acceptance is reconciled with the same ID; callers must not invent a replacement ID. |
| Claim (9), Handoff (74), Submitted (10), Start (22) | Claim assigns a generation with submission_state=0 owned by the foreground. After server-session creation and protected credential persistence, Handoff(id,generation,credential) transfers it to the platform (state=1). Submitted binds the system task (state=2) without changing its credential. Start requires state=2 for native executors; managed executor=0 requires no platform submission. Pause/cancel returns no start row; duplicate running starts fail. |
| Attempts (23), Schedulable (75) | Both take afterSequence,executor,pageSize. Attempts is an ownership inventory. Platform scheduling uses Schedulable: pending unhanded attempts are invisible; terminal unhanded attempts are visible for cleanup only. Neither query transfers ownership. |
| Finish (12) | Outcome 1 confirms the receipt, source/version relation and cleanup intent in one transaction; 2 is a known failure before uncertain server commit; 3 is interrupted/unknown; 4 proves no server commit or no network start. Confirmation wins previous cancellation intent. |
| Release (13) | Confirms actual payload/credential release. Cleanup requires all attempts released. A failed completion write must not report backup success. |
| Restart (63) | Only after positively observing the previous executor ended; resets execution to pending and native submission to handed-off (1), retaining the protected credential; requires a fresh system binding. Never restarts a recorded terminal failure. |
| RecoverAttempt (57) | Positively absent executor; releases payload ownership while retaining unknown server outcome as NeedsAttention. Managed credentials release together; native credential release remains pending until the platform removes the actual credential. A newly bound foreground owner recovers abandoned submission_state=0 generations, never active handed-off generations. |
| Action (14), Pause (15) | Per-task intent and global queue pause are independent. Unknown server outcomes cannot be discarded as canceled. |
| Operation / Select / Apply (40–42) | Durable ID + fingerprint + creation upper bound. Selection pages ≤128; application pages ≤32. WaitingForRelease is nonterminal. Repeated IDs do not execute again. |
| Cleanup (18/19/21) | Selection is advisory; execution rechecks ownership. Owns both the payload and its export directory. Failed cleanup is persisted and needs explicit retry; incomplete unfailed intents resume. |
| Scope suspend / reset (69–71), ScopeState (73) | Permission changes pause accepted scope tasks in pages of32. Reset disables scanning until all disposition pages are removed; confirmed receipts and accepted tasks survive. |
| ScanPage (32), Discover (34), ActivateScan (33) | Scan items describe membership; baseline_member marks only historical versions excluded by initialization. Changes consumed during enumeration update membership without excluding newly discovered versions. ActivateScan keeps its existing nine arguments and returns one `pending` flag: repeat with the same boundaries while true. Each call checks at most 32 prior discovery rows, withdraws missing pending sources and pauses associated tasks, then persists its source/version cursor atomically. Only the final page enables the scope. Once activation begins, ScanPage and Discover cannot modify that run; explicitly begin a new scan if its input boundary is invalid. |
| OperationCleanupPage (72) | Uses the eligible-operation index; expired headers cannot starve later eligible details. |
| Prune (50–52/67/68) | Receipts, source dispositions and minimal operation identity survive history deletion. Notification truncation invalidates old cursors. |

Command arguments are defined in the dispatch cases and are exercised by `tests/repository_tests.cpp`; C#, Java and Objective-C++ encode those typed arguments without duplicating SQL. Repository errors carry SQLite error, phase and commit uncertainty. Unknown database commit faults the attachment context until explicit shutdown/reopen. File/HTTP failures do not imply database corruption.

`UFB_FINISH` keeps source-version links separate from backup IDs: distinct content versions can legitimately receive the same idempotent server backup ID. HTTP credentials are never stored in plaintext. Tokens are encrypted by AndroidKeyStore or stored by Keychain; the shared repository stores only the protected reference.

Platform adapters reconcile orphaned running executions as NeedsAttention; they do not automatically restart an executor whose server outcome is unknown. Recorded platform/repository failures require explicit recovery. iOS record callbacks always use attempt_generation, including late callbacks.

Android submission, scheduling after reopen, and worker admission share the same system-task binding. An unstarted handed-off generation is bound using its persisted credential and generation before Start; this finishes interrupted submission and does not retry a failed transfer.

File cleanup removes an unreferenced file record in the same transaction that confirms physical cleanup. Accepted tasks retain their records until history pruning. There is no periodic sweep through retained tasks to find orphan file metadata. `tasks(file_id)` indexes reference checks; source/version indexes and the accepted batch drive discovery updates. Scan-history pruning first selects a discarded run, then deletes a bounded primary-key page from that run, leaving active baselines unvisited.

Additional executable contracts: `tests/scope_reconciliation.py` checks lost removal logs, activation across reopen, changes during enumeration and cross-scope associations; `Tests/Native~/android_backup_binding.py` runs the real Android Java scheduling/binding and JNI against the shared repository with host scheduler doubles. Device scheduling and PhotoKit behavior still need platform validation.
